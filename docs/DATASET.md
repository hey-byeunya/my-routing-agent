# 택배중계서비스 고객응대 에이전트 데이터 모음

특정 업체명·서비스명 없이, 공개된 택배중계 서비스 FAQ 페이지(질문·답변 41건)를
근거로 만든 교육용 데이터 세트입니다. 형식은 `modumall-agent/data`에서 쓰던
6개 파일 구성을 그대로 따랐습니다.

## 먼저 알아둘 것

- **모두 합성(교육용) 데이터입니다.** 대화 예시, 상담원 응답, 예약 상태 조회 결과는
  전부 만들어낸 것이며 실제 업체의 내부 데이터가 아닙니다.
- **운임표만 예외**입니다. `mockdata_courierhub.json`의 택배사별 운임(방문택배·
  다량할인택배·편의점택배)은 공개 FAQ에 게시되어 있던 값을 그대로 옮긴 실제
  스냅샷입니다. 다만 시점에 따라 바뀔 수 있으므로 "참고용"이며, 실제 서비스라면
  예약 화면·API 조회값을 우선해야 합니다.
- **업체명·서비스명은 어디에도 없습니다.** 단, CJ대한통운·롯데택배·한진택배·
  우체국택배·CU·GS25·이마트24·세븐일레븐 같은 실제 택배사/편의점 브랜드명은
  남겨뒀습니다 — 이 서비스가 중개하는 대상 택배사에 대한 사실 정보이지,
  이 데이터가 만든 대상 업체의 이름이 아니기 때문입니다.
- **숫자를 지어내지 않았습니다.** FAQ에 구체적 수치가 없는 항목(예: 소호사업자
  택배의 월별 운임 구간)은 값을 만들지 않고 "조회 필요"로 표시해뒀습니다.

## 서비스 라우팅 8구분

6개 파일 전반에서 공통으로 쓰는 분류 기준입니다. FAQ 원문의 7개 카테고리에
"응대 범위 밖" 1개를 더했습니다.

| 코드 | 이름 | 내용 |
|---|---|---|
| RESERVE_GENERAL | 택배예약 | 서비스 소개, 예약 방법, 택배사 비교, 최저가 안내 |
| VISIT_PICKUP | 방문택배 | 기사 방문수거 관련 |
| CVS_PICKUP | 편의점택배 | 편의점 직접 접수 관련 |
| BULK_DISCOUNT | 다량할인택배 | 여러 박스 동시 발송 |
| BIZ_ACCOUNT | 소호사업자택배 | 사업자 인증 기반 정기 발송 |
| ORDER_SYNC | 주문연동 | 쇼핑몰 주문 수집·운송장 자동 전송(셀러 자동화) |
| SPEC_SHIPPING | 규격·배송·취소 | 규격 측정, 배송조회, 예약 취소·변경, 반입 제한 물품 |
| OTHER | 이용범위밖 | 오프라인 매장, 타 채널 주문 처리, 입점/채용 등 응대 범위 밖 |

## 파일별 설명

### 1. `policy_courierhub.md` — CS 상담 매뉴얼
사람이 읽는 정책 문서. "무엇을 즉답해도 되고 무엇은 조회 후에만 답해야 하는지"를
원칙 중심으로 정리했습니다. 예약 절차, 규격 측정법, 운임 스냅샷, 반입 제한 물품,
쇼핑몰 연동 트러블슈팅, 응대 범위와 이관 기준, 쓰지 말아야 할 표현까지 포함합니다.
에이전트의 **시스템 프롬프트/근거 문서**로 넣기 적합합니다.

### 2. `mockdata_courierhub.json` — 조회용 목데이터
에이전트가 호출하는 "툴"이 반환할 법한 구조화 데이터입니다.
- `services`: 8개 서비스 구분별 설명·절차
- `carriers`: 방문택배·다량할인택배·편의점택배 각각의 택배사/브랜드별 운임 구간표
- `box_size_rule`, `restricted_items`, `id_glossary`, `cancel_change_rule`: 규격,
  반입 제한 물품, 예약번호/운송장번호 개념, 취소 규칙
- `today_orders_troubleshoot`, `cvs_vs_visit_guide`, `out_of_scope`: 트러블슈팅
  체크리스트, 서비스 선택 가이드, 응대 범위 밖 예시

### 3. `customer_inquiries.csv` — 합성 고객 문의 샘플 (90건)
실제 상담 로그 형태를 흉내 낸 문의-응답 샘플입니다. 8개 서비스 구분에 걸쳐
분포되어 있고, `answer` 컬럼은 확정 수치 대신 "확인 후 안내드리겠습니다" 식의
안전한 hedge 답변으로 채웠습니다(운임처럼 조회가 필요한 값을 상담원이 즉석에서
단정하면 안 된다는 매뉴얼 원칙을 반영).

| 컬럼 | 의미 |
|---|---|
| qa_id | 400001부터 순번 |
| category | 서비스 구분 (한글 라벨) |
| attribute | `일반` / `운임`(운임·가격이 핵심인 질문) |
| intent_full | `{구분}_{세부주제}_질문\|요청` 패턴 |
| sentiment | `m`(중립) / `n`(부정) |
| question / answer | 합성 질문·답변 |
| product | 문의와 관련된 택배사·브랜드명(해당 시) |
| q_len / a_len | question/answer 글자 수 |
| provenance | 항상 `합성` |

### 4. `hard_cases.csv` — 라우팅이 까다로운 사례 (45건)
분류기·에이전트가 틀리기 쉬운 경계 사례를 유형별로 모았습니다.

| hard_type | 의미 |
|---|---|
| 경계모호 | 두 서비스 구분에 걸쳐 있어 되물어야 하는 문의 |
| 극단단답 | "얼마예요?"처럼 대상이 없는 한두 단어 발화 |
| 다중의도 | 한 문장에 서로 다른 두 요청이 섞인 경우 |
| 문맥의존 | 이전 턴을 봐야만 해석되는 발화("그걸로 할게요") |
| 분류체계밖 | 애초에 8개 구분 어디에도 없는 문의(범위 밖) |
| 텍스트손상 | 오타·붙여쓰기·이모티콘 등으로 표기가 깨진 문의 |

`route_expected`/`route_alt`는 정답 라우트와, 경계모호 케이스에서 함께 고려할
수 있는 대안 라우트입니다.

### 5. `routing_answers.csv` — 라우팅 정답 + 데이터 분할
`customer_inquiries.csv`와 qa_id로 1:1 매칭되는 정답 파일입니다.

| 컬럼 | 의미 |
|---|---|
| route | 정답 라우트 코드(위 8구분 표 참고) |
| split | `eval`(평가용) / `fewshot`(프롬프트 예시용) / `outscope`(OTHER 전용) |

### 6. `answer_goldenset_multiturn.json` — 멀티턴 답변 정답셋 (15개 대화)
"라우팅만 맞으면 되는 게 아니라 실제로 옳은 답을 했는가"를 채점하기 위한
세트입니다. 각 상담원 턴마다 다음을 명시합니다.

- `action`: `ASK`(되묻기) / `ANSWER`(조회 후 답변) / `CONFIRM`(동의 필요) /
  `OUT_OF_SCOPE`(범위 밖 안내) / `ESCALATE`(상담원 이관)
- `tools` / `tool_args`: 호출해야 할 조회 함수와 인자
- `must` / `forbid` / `must_ask`: 답변에 반드시 있어야/없어야 할 문자열, 되물어야
  할 항목
- `rubric`: 왜 그 판정인지 정책 조항과 함께 설명
- `reference`: 모범 답안 예시

대표적으로 포함된 케이스: 운임 조회 강제(C-001~004), 미공개 수치 날조 금지
(C-005 소호사업자 운임), 조회 후에만 상태 안내(C-006 미방문, C-007 배송조회,
C-012 편의점 조회 불가), 동의 없는 처리 금지(C-009 취소), 반복 문의 시 이관
(C-011, C-012), 응대 범위 밖(C-013, C-014).
